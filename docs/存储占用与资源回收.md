# 存储占用与资源回收

## 管理入口

管理员进入“管理与公共资料 → 占用空间”，可查看文件分类大小、数量、业务数据库大小和业务文件磁盘剩余空间。点击刷新重新扫描；不会自动频繁轮询磁盘。列表是已统计项目，不是整台服务器总占用；数据库可能远程部署。PostgreSQL 集群目录、其他数据库、外部备份、用户个人下载、个人模板及独立模型服务器不在合计中。

统计口径已调整为：包装图片、报告附件、默认模板、业务数据库、网页发布文件、后端程序与迁移文件、运行配置及业务加密密钥、运行转换临时文件。开发/实验tmp、研究资料、旧备份、.venv、node_modules不计入。只改变统计范围，不删除这些本机文件。临时文件不必迁移；服务器依赖需重新安装，因此合计不等于目标服务器最终占用或压缩后的迁移包大小。data/credential.key须与业务数据库一起安全迁移；网关凭据需在目标服务账号下重新配置。

## 自动处理

服务启动时检查，运行期间每小时执行一次：

| 资源 | 处理方式 |
|---|---|
| 回收站记录、操作日志 | 保留30天，沿用原规则 |
| 过期登录会话 | 清理过期会话，未过期会话保留 |
| 识别任务 | 创建满30天、基础和辅助均结束、没有记录或历史快照引用时清理 |
| 包装图片 | 创建满30天，且没有记录、历史快照或保留任务引用时回收 |
| 孤立图片/报告文件 | 托管目录直属文件、无数据库对应项且修改时间满30天时回收 |
| 批量保存回执 | 所有关联记录均不存在时清理；仍有关联记录则保留幂等信息 |
| 转换临时文件 | 位于 DATA_DIR/runtime-temp；正常结束立即删除，转换异常残留超过7天定期删除 |

旧图片和旧识别任务无法可靠确定创建日期，升级时从当天重新开始30天保护期。仍被引用的资料没有年龄上限，正常业务增长仍会占用空间。

每轮最多删除各1000条旧任务、照片、孤立文件和失效回执。保存时与清理使用事务锁协调；文件在数据库提交后删除，事务回滚不删。文件路径限制在托管目录，拒绝符号链接、目录连接和越界路径。删除失败的孤立文件可在以后周期重试。

Excel、Word导出通过内存返回，不长期保存服务器导出副本。浏览器附件预览在关闭时释放Blob地址和PDF工作线程。OCR已有基础1、辅助2的并发限制。

## 本机审计快照（2026-11-16）

包装图片约185.5 MiB，报告附件约74.0 MiB，业务数据库约14.2 MiB。旧tmp约2.09 GiB、Python依赖约1.0 GiB、前端构建依赖约219.9 MiB。实时数值以页面为准。

旧tmp内包含正在使用的便携PostgreSQL程序、安装包、npm缓存及用户要求保存的模型实验，不是可整体删除的缓存。本次不自动处理旧tmp、研究资料、备份、数据库文件和运行环境。

## 迁移与持续运维

- 在服务器重新安装Python依赖，发布frontend/dist，不必迁移frontend/node_modules、开发缓存和实验目录。实验报告与研究资料单独归档。
- 通过数据库备份/恢复迁移业务库；同时迁移DATA_DIR/images、report-attachments及模板。不要直接删除PostgreSQL目录或WAL。
- 本机当前PostgreSQL可执行程序在tmp/pg-runtime，不能在仍依赖它时删除整个tmp。
- 数据库autovacuum负责复用空间；删除记录后磁盘文件不一定立即缩小，不自动执行会锁库的VACUUM FULL。
- 备份需按公司要求制定独立保留周期；运行日志应由部署平台配置轮换和容量告警。应用不擅自删除这些资料。
- 目前Office转换有超时，但没有新增全局并发上限；公司多人并发大量导出时，应按服务器容量限制并发和请求体大小。
- 数据量极大时，空间扫描和历史引用检查成本随文件/历史数量增长；本次保证按需统计与按小时回收，尚未改成独立存储索引服务。
