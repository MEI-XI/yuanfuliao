# 接口与测试计划

依据项目方案，2026-10-14 开始实施。三个测试入口已获用户确认。

## 对外接口

接口统一 `/api` 前缀，浏览器同源访问，登录采用 HttpOnly 会话 cookie。公开接口仅初始化状态、首次初始化及登录；业务内容均要求登录。服务端使用当前会话判断创建人和角色，不能信任浏览器传来的用户标识。

| 流程 | 接口 |
| --- | --- |
| 初始化与登录 | GET/POST setup，POST login/logout，GET me |
| 账号维护 | GET/POST users，PATCH users/{id} |
| 公司台账 | GET/POST ledgers，PATCH ledgers/{id} |
| 记录 | GET/POST ledgers/{id}/records，GET/PATCH records/{id} |
| 核对与作废 | POST records/{id}/check、void，GET records/{id}/history |
| 公共资料 | materials、schemes、partners 的读取和管理员维护 |
| 图片及识别 | 上传图片，创建识别任务，轮询任务，本地结果和云端建议分开 |
| 导出 | POST exports/xlsx、exports/docx，传记录标识与待核对确认标志 |
| 打印预览 | POST previews/xlsx、previews/docx，使用相同导出输入，返回实际导出文件转换的 PDF |
| 保质期推算 | POST shelf-life/derive，生产日期、期限、到期日，返回补全值与核对提示 |
| 报告附件 | GET/POST records/{id}/reports，GET reports/{id}/file、preview，DELETE reports/{id}?version= |

所有记录编辑传入版本号；后台通过数据库原子更新拒绝过期版本，HTTP 409 提示重新读取。核对和作废同样检查版本。公司名称校验 Excel 表名约束及重名。

## 逐条 TDD 顺序

每一项分别经历测试失败和通过，前一项完成后才添加下一项。

1. 首次初始化、登录、初始化关闭。
2. 管理员创建账号，普通账号无法提升角色；停用后会话失效。
3. 创建公司台账，普通账号只能选择，名称能用于 Excel 表名。
4. 保存空白记录，默认北京时间日期，明确清空后不再填回。
5. 所有人可读，只有创建人或管理员能改、核对；修改保留历史并回待核对。
6. 版本冲突拒绝，作废只允许管理员。
7. 共享物料多套标准，记录采用快照；单位资料保持来源标记。
8. 从 HTTP 下载检查 XLSX 内容、DOCX 日期与空值、ZIP 报告数量。
9. 图片受登录保护，任务先产出本地结果；云端错误后仍可保存。
10. 浏览器登录、台账录入、图片分组、来源建议与手动字段保护，手机布局。
11. 包装随共享物料带入、唯一绑定方案自动选择、多方案等待选择、另存项目不复制检验结果。
12. 保质期按日历计算再减一天，最早生产日期、反推期限、冲突、人工改写及清空、乱序请求。
13. 报告附件的权限、版本冲突、预览、恢复、三十天清理和表单未保存内容保留。
14. 真实 Office PDF 预览、个人模板、多报告顺序、横向 Excel 分页、手机缩放及浏览器打印调用。
15. 保存等待自动计算期间切换分组或页面，仍只保存发起操作时选定的记录及台账。

## 开发与验收分界

自动测试不得将标签“合格”当成检验结论，不从单包净含量推算接收数量，不增加 Excel 批号列。

模板版式以原文件为依据，生产日期批号栏以点分年月日填入。真实 OCR 样本对照、Word/WPS 打印和用户手机操作单独记录，不能用模拟云端响应证明真实模型准确率。
