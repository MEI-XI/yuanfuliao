# OCR 实测

## 样本与方法

2026-10-14，经用户授权读取指定图片目录的 13 张照片。先保存未经本轮改进的输出，再逐张查看照片、记录主名称和明确可读的生产日期，最后在同一批照片上运行改进流程。历史 Excel 只作对照，不向新批次识别结果补入历史日期、数量或检验结果。

用户历史台账文件名含“2025年7月”，实际内容延续至2026年，不能用文件名判断全部记录时期。存在同类不同厂家、不同包装规格和简写名称，不应将这些业务差异当作 OCR 字符错误。

本地逐张明细位于 `data/qa/识别对照报告.md`。原图、台账提取数据、模型输出和人工标注均不上传 GitHub。`scripts/benchmark_ocr.py` 可重新识别目录；`scripts/compare_ocr_samples.py` 根据独立标注比较输出，生产应用不会读取基准答案。

## 2026-10-14 默认模型与调整

采用 RapidOCR 3.10.0，通过 ONNX Runtime 运行 PP-OCRv6 small 检测和识别模型，方向分类为 ch_ppocr_mobile_v2.0_cls。明确指定版本及模型大小，避免上游默认配置改变。

改进包括四方向识别、根据标签位置关联分离字段、产品标题优先于品牌和搬运标识、连续数字生产日期、规格与净含量提取、一次倾斜校正、四块重叠局部识别。局部裁剪可能截断名称和公司，因此自动补充仅限缺失的日期、联系方式、保质期，冲突仍需人工核对。净含量只进入规格，不进入接收数量。

供应商与生产商分别提取后按供应商优先；地址、电话不能确定归属时不编造来源。未识别或有歧义的字段可以留空，保存原文及照片供人员复核。云端建议不自动覆盖人工填写。

## 对照模型

本机 i5-14400、约16GB内存，CPU运行。比较为工程选型观察，模型版本、照片角度和处理轮数不完全相同，不是统一的公开模型排行榜。

- RapidOCR 初始轻量流程在13图上单图约6～9秒；加入倾斜与局部识别后约11～19秒，以本地明细记录为准。
- 同引擎增大检测尺寸至1280，在13图中没有稳定改善关键文字，未采用。
- RapidOCR + PP-OCRv5 server 检测与识别在前三张四方向处理约71～125秒，仍有公司名称拆分、个别字段丢失，未作为默认；该实验提前结束，其余10张未跑server模型。
- PaddleOCR 3.7 + PaddlePaddle 3.3.1 的 PP-OCRv5 mobile 在甘氨酸单图预先转正实验中初始化约2.2秒、推理约16.4秒；需关闭MKLDNN才能在当前环境运行。结束时进程内存约407MB，对照轻量Rapid约112MB（均非峰值，也不是严格相同配置）。未纳入生产依赖。

## 解释结果

本组主名称由4/13提升为11/13，明确生产日期由5/10提升为10/10。名称按照片中人工确认的主名称完整出现计数，日期按完整年月日精确匹配；这不是全部字段准确率。牛油的附加数字、羊肚油空白日期、鸡蛋黄粉未清晰展示日期不计日期分母。

消泡剂和鸡蛋黄粉的完整名称仍需手动填写或补拍。小字厂家、地址电话仍有漏识别或错字，例如“茌平”被识别为“在平”，局部地址可能不完整。历史台账自身也有简写和疑似录入错误，不能直接作为所有字段的标准答案。

这些样本参与了调优，不能据此推断其他包装的准确率。以上为当时本地模型比较；后续云端实测记录如下，仍需补充未参与调优的真实包装验收。

## 2026-10-18 英文识别与翻译实测

使用生成的清晰英文标签验证实际 RapidOCR 模型。十行内容涵盖 Product Name、Manufacturer、Net Weight、MFG、EXP、Shelf Life、Packaging、Address、Tel、Batch No。本地最终一次运行约11.1秒，正确得到 Glycine、25 kg/bag、24个月、生产日期2026-01-14、到期日2028-01-13，以及厂家、地址、电话、包装和批号。该样本用于检查流程，不能代表折皱、反光、模糊英文包装的准确率。

使用现有配置的 GLM-4.1V-Thinking-Flash 真实调用。最初响应带 JavaScript 注释和尾逗号导致 JSON 解析失败，并误读提示词中的日期排除规则。增加只清理字符串外注释及尾逗号的兼容处理；提示词明确翻译自然语言、保留号码和批号，并将日期排除规则限定为日期判别。最终实测返回“甘氨酸”“纸袋”“伦敦食品路10号”，电话、批号及两个日期保持正确。厂家名称仍保留英文原名，需人员核对。原始响应及密钥不提交代码仓库。

## 2026-11-03 名称候选与人工确认名称

当前基础识别使用内网网关的 PaddleOCR-VL-1.5-0.9B，智谱仍为可关闭的辅助识别；本轮修改字段整理和候选填入规则，未更换模型或改动密钥配置。

名称不再要求以“酸、粉、油”等固定词尾结束。优先明确的品名标签，再结合产品标题、字号和上下文形成候选；保留“制品”等完整名称以及明确型号，过滤厂家、品牌和说明文字。没有明确品名标签的标题可以先默认填入，同时在名称框下方提示核对并保留候选。多个名称尚不能确定同一物料时，不套用历史检验信息。

本次识别与已核对记录名称明确一致时，采用人员确认的名称写法。共享物料中唯一、明确匹配的维护名称或别名可以映射到完整名称；一个别名对应多种物料时保留选项，不任选一项。“鸡蛋黄粉”和“鸡蛋黄粉制品”不会通过删除词尾强行视为同一物料。历史识别有多个候选、后来经人员核对的记录，可按最终确认名称匹配，未选中的其他候选不会自动学成别名。

历史复用仍使用最近的已核对记录，人员本次已修改的字段保留；日期、保质期、到期日及接收数量不沿用历史。基础识别和云端返回不同名称时保留候选，先默认有依据的读法，但不凭其中一个名称恰好有历史就复用整条检验信息。英文原文保留供核对，云端中文译名可以默认填入空白名称框。

“20kg/”等残缺规格保留为候选并提示核对；存在明确完整净含量时可先填入净含量，不补猜包装单位。识别只返回“保质期：12”时不自动猜成12个月；人员主动输入数字按月录入的原有规则保持。云端同时返回完整字段和残缺候选时，两者均保留。

验证通过后端接口与浏览器操作覆盖候选默认填入、切换选择、精确历史匹配、型号与别名、名称冲突、人工值保护以及云端不可用继续使用基础结果。另回放之前保存的13张图片的真实网关输出，检查字段整理规则；这属于固定识别结果回放，不代表模型本身识字准确率提高，也未重新计算三模型比较分数。
